# Site Studio Development Guide

This guide documents the development workflow and process management for Site Studio, particularly the solutions implemented to prevent orphan processes.

## The Orphan Process Problem

### Background

When running `npm run dev`, the application creates a complex process tree with 13+ nested processes:

```
npm run dev (PID 1000)
  └─ sh -c concurrently ... (PID 1001)
      └─ node concurrently (PID 1002)
          ├─ npm run dev:backend (PID 1003)
          │   └─ npm workspace command (PID 1004)
          │       └─ sh -c tsc && node ... (PID 1005)
          │           └─ node dist/index.js (PID 1006) ⭐ BACKEND SERVER
          └─ npm run dev:frontend (PID 1007)
              └─ npm workspace command (PID 1008)
                  └─ sh -c vite dev (PID 1009)
                      └─ node vite (PID 1010) ⭐ FRONTEND SERVER
```

### The Problem

When you stop the parent process (via Ctrl+C or kill command), **signals don't propagate properly** through this deeply nested structure. This results in:

1. Parent npm process exits
2. Child processes become orphaned (adopted by init/PID 1)
3. Actual server processes (backend on 3001, frontend on 5173) keep running
4. Ports remain occupied
5. Next `npm run dev` fails with "Address already in use"

### Why npm Can't Solve This

- npm spawns processes with shell wrappers (`sh -c`)
- Shell doesn't automatically forward signals to background processes
- Each layer adds more indirection
- By the time signal reaches the bottom processes, it's often lost
- Process groups are broken by the multiple shell layers

## The Solution: Shell Script Wrapper

Instead of relying on npm's nested process structure, we use a bash script (`dev.sh`) that:

1. **Creates a proper process group** - All processes are in the same group
2. **Uses `trap` for signal handling** - Catches SIGINT/SIGTERM/EXIT reliably
3. **Tracks PIDs directly** - Knows exactly which processes to kill
4. **Implements graceful shutdown** - Tries SIGTERM first, then SIGKILL if needed
5. **Validates startup** - Checks ports and health before declaring success

### Stopping Servers

**Graceful shutdown:**
```bash
# While dev.sh is running, press Ctrl+C
# This triggers the cleanup function which:
# 1. Sends SIGTERM to both processes
# 2. Waits up to 5 seconds for graceful exit
# 3. Force kills if needed (SIGKILL)
# 4. Waits for all background jobs to complete
```

### Cleaning Up Orphan Processes

If processes somehow become orphaned (rare with dev.sh, but possible):

```bash
./scripts/cleanup-ports.sh

# This will:
# - Find all processes on ports 3001 and 5173
# - Try graceful kill (SIGTERM) first
# - Force kill (SIGKILL) if needed after 5 seconds
# - Clean up any other site-studio related processes
```

## Architecture

### Backend (Port 3001)

- **Framework:** Express.js
- **Location:** `packages/backend/`
- **Entry point:** `src/index.ts`
- **Graceful shutdown:** ✅ Implemented (lines 1532-1562 in index.ts)
  - Closes HTTP server
  - Cleans up sandbox sessions
  - 10-second timeout for forced exit

### Frontend (Port 5173)

- **Framework:** SvelteKit + Vite
- **Location:** `packages/frontend/`
- **Dev server:** Vite
- **Proxies:** `/api` and `/preview` routes to backend

## Logs

When using `./dev.sh`, logs are written to:

- **Backend:** `backend.log` in project root
- **Frontend:** `frontend.log` in project root

These files are created fresh on each run and can be tailed while servers are running:

```bash
# In another terminal
tail -f backend.log
tail -f frontend.log
```

## Troubleshooting

### "Address already in use" Error

**Symptom:**
```
Error: listen EADDRINUSE: address already in use :::3001
```

**Solution:**
```bash
./scripts/cleanup-ports.sh
```

This happens when:
- Previous dev processes didn't shut down cleanly
- You killed processes without using Ctrl+C in dev.sh
- A crash left processes running

### Backend Fails to Start

**Check the logs:**
```bash
tail -n 50 backend.log
```

**Common causes:**
- TypeScript compilation errors
- Missing environment variables
- Database/storage connection issues
- Port already in use

### Frontend Fails to Start

**Check the logs:**
```bash
tail -n 50 frontend.log
```

**Common causes:**
- Backend not running (frontend proxies to backend)
- Port 5173 already in use
- Node modules out of date (`npm install`)

### Processes Still Running After Ctrl+C

This should be rare with `dev.sh`, but if it happens:

1. Run the cleanup script:
   ```bash
   ./scripts/cleanup-ports.sh
   ```

2. If that doesn't work, manually find and kill processes:
   ```bash
   # Find processes on specific ports
   lsof -ti:3001 -ti:5173

   # Kill them
   kill -9 $(lsof -ti:3001 -ti:5173)
   ```

## Development Workflow

### Typical Development Session

```bash
# 1. Start servers
./dev.sh

# 2. Open browser to http://localhost:5173

# 3. Make changes to code
#    - Backend: Changes require restart (Ctrl+C, then ./dev.sh again)
#    - Frontend: Hot reload happens automatically

# 4. Check logs if something goes wrong
tail -f backend.log
tail -f frontend.log

# 5. When done, press Ctrl+C
#    Servers will shut down gracefully
```

### Making Backend Changes

The backend uses `tsc && node dist/index.js` which means:
- Changes to TypeScript files require manual restart
- Press Ctrl+C in dev.sh
- Run `./dev.sh` again

**Future improvement:** Consider using `tsx watch` for hot reload.

### Making Frontend Changes

The frontend uses Vite which provides:
- Hot Module Replacement (HMR)
- Instant updates in browser
- No restart needed

## Technical Details

### Signal Handling

**Backend (`packages/backend/src/index.ts`):**
```typescript
// Lines 1560-1562
process.on('SIGTERM', () => gracefulShutdown('SIGTERM'));
process.on('SIGINT', () => gracefulShutdown('SIGINT'));
```

The graceful shutdown function:
1. Logs the shutdown signal
2. Closes the HTTP server (stops accepting new connections)
3. Cleans up sandbox sessions
4. Exits with status code 0 (success) or 1 (error)
5. Forces exit after 10 seconds if cleanup hangs

**dev.sh Script:**
```bash
# Line 15-16
trap cleanup EXIT INT TERM
```

The cleanup function in dev.sh:
1. Prevents multiple cleanup calls
2. Kills backend process (SIGTERM → wait → SIGKILL if needed)
3. Kills frontend process (SIGTERM → wait → SIGKILL if needed)
4. Waits for all background jobs
5. Exits cleanly

### Process Tree with dev.sh

Much simpler than npm-based approach:

```
bash dev.sh (PID 1000)
  ├─ npm run dev [backend] (PID 1001)
  │   └─ node dist/index.js (PID 1002) ⭐ BACKEND
  └─ npm run dev [frontend] (PID 1003)
      └─ node vite (PID 1004) ⭐ FRONTEND
```

Only ~5 processes instead of 13+, and the bash script has direct control over the backend/frontend npm processes.

## Alternative: Using npm Scripts

If you still want to use `npm run dev` (not recommended due to signal propagation issues):

```bash
npm run dev
```

**Known limitations:**
- Ctrl+C may not cleanly kill all processes
- Orphan processes more likely
- Requires manual cleanup more often
- Signal handling less reliable

If you use this approach, keep `./scripts/cleanup-ports.sh` handy.
